UniRenter backend
setup guide.

A step-by-step guide to setting up Supabase, Vercel, and your custom domain this weekend — no prior experience required. By the end, UniRenter will be live at unirenter.com.au with a real database behind it.
⏱️
Estimated time: 3–5 hours total, spread across the weekend. Most steps take 5–15 minutes. The DNS propagation in Step 4 is the only thing you'll wait on.

Phase 1 — Accounts & infrastructure

Do this first — Saturday morning
STEP 1

Create your Supabase account & project

Supabase is your database, authentication, and file storage — all free to start.

  • Go to supabase.com → click Start your project → sign up with GitHub (easiest) or email
  • Click New project → name it unirenter
  • Choose region: ap-southeast-2 (Sydney) — closest to your users
  • Set a strong database password → save it somewhere safe
  • Click Create new project — takes ~2 minutes to spin up
✅
Free tier gives you 500MB database, 1GB file storage, 50,000 monthly active users. More than enough to launch and validate UniRenter.
STEP 2

Create your database tables

In your Supabase project, go to SQL Editor and run the following. This creates the core tables UniRenter needs:

-- Users / profiles
CREATE TABLE profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  phone TEXT UNIQUE,
  email TEXT UNIQUE,
  first_name TEXT,
  city TEXT DEFAULT 'melbourne',
  student_status TEXT,
  university TEXT,
  photo_url TEXT,
  country_residence TEXT,
  country_origin TEXT,
  gender TEXT,
  looking_for TEXT,
  budget_min INT,
  budget_max INT,
  move_in TEXT,
  sleep_schedule TEXT,
  cleanliness TEXT,
  social_vibe TEXT,
  smoking TEXT,
  pets TEXT,
  party_habits TEXT,
  guests TEXT,
  suburbs TEXT[],
  accom_types TEXT[],
  gender_pref TEXT,
  deal_breakers TEXT[],
  ai_summary TEXT,
  agent_optin BOOLEAN DEFAULT FALSE,
  agent_contact_method TEXT,
  agent_email TEXT,
  verified_phone BOOLEAN DEFAULT FALSE,
  verified_email BOOLEAN DEFAULT FALSE,
  verified_student BOOLEAN DEFAULT FALSE,
  is_active BOOLEAN DEFAULT TRUE
);

-- Matches / connections
CREATE TABLE connections (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  from_user UUID REFERENCES profiles(id),
  to_user UUID REFERENCES profiles(id),
  status TEXT DEFAULT 'pending',
  message TEXT
);

-- Messages
CREATE TABLE messages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  connection_id UUID REFERENCES connections(id),
  sender_id UUID REFERENCES profiles(id),
  content TEXT,
  read BOOLEAN DEFAULT FALSE
);

-- Agent leads
CREATE TABLE agent_leads (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  profile_id UUID REFERENCES profiles(id),
  city TEXT,
  budget TEXT,
  suburbs TEXT[],
  accom_type TEXT,
  move_in TEXT,
  contact_method TEXT,
  contact_email TEXT,
  agent_email TEXT DEFAULT 'benjcarey75@gmail.com',
  status TEXT DEFAULT 'new',
  notes TEXT
);

-- Lease listings
CREATE TABLE lease_listings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  poster_id UUID REFERENCES profiles(id),
  city TEXT,
  suburb TEXT,
  property_type TEXT,
  weekly_rent INT,
  bond INT,
  lease_end TEXT,
  landlord_consent TEXT,
  description TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  docs_uploaded BOOLEAN DEFAULT FALSE
);

-- Reports
CREATE TABLE reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  reporter_id UUID REFERENCES profiles(id),
  reported_profile_id UUID,
  category TEXT,
  detail TEXT,
  status TEXT DEFAULT 'pending'
);
✅
Paste the whole block into SQL Editor and click Run. All tables created in one go.
STEP 3

Get your Supabase API keys

In your Supabase project: Settings → API. You need two values:

  • Project URL — looks like https://xxxxx.supabase.co
  • anon/public key — a long JWT string starting with eyJ...

Save these somewhere — you'll need them in Step 5.

⚠️
Never share the service_role key publicly. The anon key is safe to use in frontend code.

Phase 2 — Domain & hosting

Saturday afternoon
STEP 4

Buy unirenter.com.au

  • Go to netfleet.com.au or GoDaddy.com.au — search unirenter.com.au
  • If available: purchase it (typically $15–30/yr for .com.au)
  • If taken: check whois.ausregistry.com.au to see who owns it and when it expires. If it expired recently, services like Netfleet can help you backorder it.
  • Once purchased, log into your registrar — you'll update DNS records in Step 6
ℹ️
.com.au requires an Australian Business Number (ABN) or matching business name. If you don't have one yet, unirenter.com or unirenter.app work as alternatives while you get set up.
STEP 5

Create your Vercel account & deploy

Vercel is your hosting platform — it makes your HTML files into a live website with HTTPS automatically.

  • Go to vercel.com → Sign up → use GitHub (create a free GitHub account first if needed)
  • On GitHub: create a new repository called unirenter → upload all your HTML files into it
  • Back on Vercel: click Add New Project → Import Git Repository → select your unirenter repo
  • Click Deploy — Vercel builds and deploys in ~30 seconds
  • You get a free URL like unirenter.vercel.app — your site is live!
✅
Every time you push new files to GitHub, Vercel automatically redeploys. This is your update workflow going forward.
STEP 6

Connect your domain to Vercel

This makes unirenter.com.au point to your Vercel deployment.

  • In Vercel: go to your project → Settings → Domains → type unirenter.com.au → click Add
  • Vercel gives you two DNS records to add (a CNAME and an A record)
  • Log into your domain registrar → find DNS Management → add those two records exactly as shown
  • Wait 10 minutes to 24 hours for DNS to propagate — this is normal
  • Once done: unirenter.com.au loads your site with automatic HTTPS
⏱️
DNS propagation is the one thing you can't rush. Set it up Saturday afternoon and check Sunday morning — it's almost always done by then.

Phase 3 — Wire it all together

Sunday
STEP 7

Add Supabase to your HTML files

Add this to the <head> of your main HTML files:

<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
<script>
  const supabase = window.supabase.createClient(
    'YOUR_SUPABASE_URL',
    'YOUR_SUPABASE_ANON_KEY'
  );
</script>

Replace YOUR_SUPABASE_URL and YOUR_SUPABASE_ANON_KEY with the values from Step 3.

✅
That's it — you can now save and read data from your database with 2-3 lines of JavaScript. No backend server needed.
STEP 8

Test: save your first profile

Add this test snippet temporarily to verify the connection works:

// Test — save a profile
const {{ data, error }} = await supabase
  .from('profiles')
  .insert({{ first_name: 'Test', city: 'melbourne', phone: '+61400000000' }});

console.log('Result:', data, error);

Open your browser console (F12) — if you see the data object with no error, everything is working.

STEP 9

Set up agent lead email notifications

In Supabase: go to Database → Webhooks → create a new webhook:

  • Table: agent_leads
  • Events: INSERT (fires when a new lead is saved)
  • URL: use Resend.com (free email API) — sign up, get API key, use their webhook URL

This fires an email to benjcarey75@gmail.com automatically every time a student ticks the agent opt-in box. The email includes all their housing preferences.

📧
Resend.com free tier: 3,000 emails/month. More than enough to start. When you onboard an agent partner, you simply update the agent_email field in the database.
